## 评审支撑：建议补充

1. 业务效果对比：当前已实现同一输入版本上的基准对比，但只有小型体验案例的保存结果。建议补充代表性、明确标注来源的多任务输入与输出；相同完成量下再比较费用，不把功能测试写成企业效率提升。
2. 规模验证：当前有 50 订单 / 15 车辆的输入限制和 2 个计算线程，尚无并发或规模压测报告；记录求解耗时、道路服务等待时间、失败和资源使用情况后再形成性能结论。
3. 模型评测：本地分类模型已有功能测试，但没有正式独立评测报告。需要时补充未参与训练的语句集、标注规则及错误分析，不能直接以训练集成绩充当泛化结果。
4. 企业验证：当前缺少真实运营数据与无人车平台，先进行获得授权的离线试点，再核验通行规则、遥测与任务下发。

这些属于增强评审说服力的建议，不是官网额外要求的固定报告模板。

## 打包与仓库文件

包含源码、依赖锁文件、`setup.ps1`、`start.ps1`、`run.py`、README、API、演示及接入文档、测试与验收记录。ZIP 包额外带预构建前端。

默认排除 `.venv/`、`node_modules/`、`.env`、运行数据库、缓存、私人订单和账号数据。保留 `.env.example` 供配置说明。Git 默认忽略 `frontend/dist/`；从源码安装时运行 `setup.ps1` 会重新构建。

如果不把完整 ZIP 放入仓库，源码及文档仍应在仓库内完整可访问。提交前核对 README 中所有相对链接，避免上传文档却遗漏其引用的材料。
